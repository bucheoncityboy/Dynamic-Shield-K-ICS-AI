## 4.2 전체 아키텍처

**구성 체크 결과**: 4.2.1~4.2.5는 제안 아키텍처와 동일하게 구현되어 있다. 프로젝트에는 **4.2.6 K-ICS Surrogate**, **4.2.7 XAI**가 추가되어 있으며, HMM은 **4개 국면**(Normal, Transition, Safe-haven, Panic), Safety는 **Level 1(130%)·Level 2(100% 또는 VIX≥40)·Level 3(손절)** 3단계로 구현되어 있다.

```
[시장 데이터] → [국면 인식] → [의사결정] → [안전 검증] → [헤지 신호]
     ↓              ↓            ↓            ↓
  VIX, FX,      HMM 기반      PPO 강화학습   Safety Layer
  Correlation   국면 분류     최적 전략 학습  위기 대응
```

### 4.2.1 데이터 입력 및 전처리 (Market Data Input)

시스템의 입력층은 시장의 거시적 위험과 자산 간 역학 관계를 포착하는 **다변량 시계열 데이터**로 구성된다.

| 구분 | 내용 |
|------|------|
| **주요 변수** | 변동성 지수(VIX), 환율(FX) 시계열, 주식-환율 **60일 이동 상관계수**, 한·미 금리차 대리 변수(Yield Spread) |
| **HMM용 확장 변수** | VIX 변화율(VIX_Change), 환율 이격도(FX_MA_Divergence), Yield_Spread, Correlation (`core/regime.py`) |
| **데이터 소스** | 실제 데이터: `DATA/data/Dynamic_Shield_Data_v4.csv` (5,292일), Train 70% / Test 30% 분리 (`core/realistic_data.py`) |
| **역할** | 강화학습 에이전트가 현재 시장 위치를 파악할 수 있는 **관측 공간(Observation)**의 기초 데이터 제공 |

### 4.2.2 HMM 기반 국면 인식 (Regime Recognition)

수집된 데이터를 바탕으로 **은닉 마코프 모델(HMM)**을 통해 현재 시장의 잠재 상태를 추론한다.

| 구분 | 내용 |
|------|------|
| **관측 변수** | VIX, VIX_Change, FX_MA_Divergence, Yield_Spread, Correlation (`core/regime.py`) |
| **상태 분류** | **4개 국면**: Normal(안정), Transition(전환), Safe-haven(안전자산 선호), Panic(위기). VIX 평균 기준으로 상태 매핑. |
| **구현** | `GaussianHMM`(hmmlearn), `RegimeClassifier.fit()` / `predict()` / `get_state_label()` |
| **역할** | 고차원 노이즈 데이터를 **의미 있는 국면 정보**로 추상화하여 의사결정 모듈에 전달. (논문상 3개 국면 설명과 대응 시 Safe-haven을 Transition/Panic과 통합해 해석 가능.) |

### 4.2.3 PPO 강화학습 기반 의사결정 (Decision Making)

추론된 시장 정보와 실시간 K-ICS 자본비율을 바탕으로 **PPO(Proximal Policy Optimization)** 에이전트가 최적 행동을 도출한다.

| 구분 | 내용 |
|------|------|
| **상태(State)** | [현재 헤지 비율, VIX 정규화, 상관계수 정규화, SCR 비율] (4차원 Box). 국면은 VIX·상관계수에 함축. |
| **행동(Action)** | 연속 [-1, 1] → 헤지 비율 **조정량 ±10% per step** (gym: `hedge_change = action * 0.1`). |
| **보상(Reward)** | 자본 효율성 − 헤지 비용(연 1.5% 일할) − **Turnover Penalty** − K-ICS 위반 페널티(100% 미만 강한 페널티, 130% 미만 구간 경고 페널티). |
| **구현** | `core/gym_environment.py`(KICSGymEnv), `core/ppo_trainer.py`(PPO, stable-baselines3). |
| **역할** | 규제 준수 페널티와 헤지 비용·거래 비용 최소화가 통합된 보상 함수로 **자본 효율성 극대화** 정책 학습. |

### 4.2.4 다단계 안전 검증 (Safety Verification)

에이전트가 산출한 전략이 보험사 규제 가이드라인을 준수하는지 **Safety Layer**에서 최종 검증한다.

| 단계 | 발동 조건 | 개입 조치 | 규제적 근거 |
|------|-----------|-----------|-------------|
| **Level 1 (Buffer)** | K-ICS 비율 **130% 미만** | 헤지 비율 **점진적 상향**(De-risking, step 10%) | 적기시정조치 예방 |
| **Level 2 (Crisis)** | K-ICS **100% 미만** 또는 **VIX ≥ 40** | **즉시 100% 전액 헤지** 강제 | 규제 위반 방지, 시장 유동성 위기 대응 |
| **Level 3 (Protection)** | 자본 감소 한도 초과 시 | 즉각 **손절** 정책 수행 (설계 반영, 상세 로직은 운영 정책에 따라 확장) | 재무 건전성 유지 |

**Constraint**: 급격한 시장 충격 방지를 위해 1회 리밸런싱 폭을 **최대 10%(Gym) 또는 15%(Safety 모듈 설정)** 이내로 제한. (`config/base_config.yaml` → `agent.max_hedge_change`, `gym_environment` 내 ±0.1)

**구현**: `safety/risk_control.py`(RiskController, RiskConfig), `core/agent.py`(DynamicShieldAgent).

### 4.2.5 헤지 신호 출력 (Final Hedge Signal)

모든 검증을 통과한 **최종 헤지 비율**이 실제 운용 프로세스에 적용 가능한 헤지 신호로 출력된다.

| 구분 | 내용 |
|------|------|
| **출력 형태** | 0~1 연속값(헤지 비율). 백테스트·실시간 모드에서는 일 단위(또는 설정 주기) 신호로 사용. |
| **활용** | K-ICS **내부모형** 하에서 보험사의 동적 환위험 관리 지침으로 활용. (`validation/backtest.py`, `realtime/live_mode.py`) |

### 4.2.6 K-ICS Surrogate 모델 (고속 근사)

강화학습 중 수만 번 호출되는 K-ICS/SCR 계산의 연산 부하를 줄이기 위해 **DNN Surrogate**를 사용한다.

| 구분 | 내용 |
|------|------|
| **입력** | 헤지 비율, 상관계수 (및 필요 시 확장). |
| **출력** | K-ICS 비율 또는 SCR 비율 근사값. |
| **성능** | MAPE 약 0.05% 수준, 추론 10ms 미만. (`core/kics_surrogate.py`) |
| **역할** | 학습·백테스트 시 **실제 K-ICS 엔진 대체**로 실시간에 가까운 의사결정 지원. (로드 실패 시 실제 엔진 폴백.) |

### 4.2.7 설명 가능 AI (XAI)

“왜 해당 헤지 비율인가?”에 대한 근거를 제시하기 위해 **SHAP** 등 XAI를 활용한다.

| 구분 | 내용 |
|------|------|
| **도구** | SHAP(SHapley Additive exPlanations). (`validation/shap_analysis.py`) |
| **요인** | 상관계수, VIX, 국면(Regime) 등이 의사결정에 미치는 기여도 정량화. |
| **역할** | 감독·보고 시 **의사결정 투명성** 확보 및 규제 대응. |
